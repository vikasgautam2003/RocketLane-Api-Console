1. What the app does

RL Console is a small desktop app that lets a Rocketlane operator (or anyone with API access) do three things, faster:

  1. Generate a curl from plain English. Type "create a task with start date and effort"; Claude returns a curl with {{Placeholder}} variables.
  2. Fire a single request with values typed inline, or fire bulk requests by uploading a CSV — Claude maps each {{Placeholder}} to a CSV column.
  3. Auto-paginate GET endpoints, see live progress, ETA, abort mid-fetch, and export the raw items as CSV.

Everything happens locally. No backend service. The only network calls are to:

  • api.anthropic.com — for Claude (mapping + curl generation)
  • api.rocketlane.com — for the actual operations
Why a desktop app at all? Anthropic's CORS policy on Vikas's org blocks browser-origin calls. A Tauri shell with a Rust HTTP command sidesteps this — see Tauri layer and native_http_post.

How it actually runs

npm run tauri dev starts next dev on :3000, then opens a Tauri window pointing at it. npm run tauri build runs next build (which exports static HTML/JS to out/ because of output: 'export' in next.config.ts), then bundles that out/ into a .dmg/.app.

This is not a server-rendered Next.js app. Because of output: 'export', there is no Node runtime in production. No API routes, no getServerSideProps, no middleware. Everything is client-side React talking to Tauri commands.

3. The three flows

The whole app exists to support these three flows. Internalising them is the fastest way to navigate the code.

Flow A — Generate a curl from a description

  1. User types a description into the "generate" input on app/page.tsx.
  2. handleGenerateCurl() in page.tsx calls generateCurl() in lib/generate-curl.ts.
  3. generateCurl() calls the native_http_post Tauri command (in Rust) which POSTs to api.anthropic.com and returns the raw response body.
  4. The returned curl text is dropped into the Curl Command textarea.

Flow B — Bulk run with CSV mapping

  1. User pastes/edits a curl, uploads a CSV, fills context.
  2. Clicks Preview Mapping → handlePreviewMapping() calls extractMapping() in lib/claude.ts, which sends the curl + sample CSV to Claude and gets back a strict JSON template (validated with Zod).
  3. MappingPreviewModal shows the resolved request for row 1.
  4. User confirms → handleRun() → runRows() loops over CSV rows, calling executeRow() per row.
  5. executeRow() uses buildRequest() to substitute placeholders, then httpFetch() (which routes through Tauri's HTTP plugin) to send the request.
  6. Logs stream into LogPanel with progress + ETA.
  7. On finish, the run is saved to SQLite via saveRun().

Flow C — GET with auto-pagination

  1. If the curl method is GET, mode toggle is locked, "Run" is enabled with just placeholders filled.
  2. handleRun() detects GET and calls executeRow() once with an onPageFetched callback.
  3. The GET branch in executeRow() loops through pages while a nextPageToken is returned (and hasMore !== false), up to MAX_PAGES = 200.
  4. After each page it fires the callback so the UI can update fetchProgress live.
  5. Results are either expanded as one log entry per item (≤ 200 items) or summarised with raw items attached (LogEntry.items) for CSV export.
  6. Aborting flips abortRef.current = true; the loop returns partial results as 'skipped'.

6. Tauri (Rust) layer — src-tauri/

This layer is small but load-bearing. Two responsibilities: (1) the native HTTP command that bypasses Anthropic's CORS, (2) plugin registration for SQLite, the HTTP fetch plugin, and dialogs.

src-tauri/src/main.rs
Binary entry point — 6 lines

Calls app_lib::run(). Don't change.

src-tauri/src/lib.rs
The Tauri builder + the only custom Rust command

Two things to know:

  1. native_http_post — a #[tauri::command] that takes url, headers, body strings and POSTs them via reqwest. The TS side calls it with invoke('native_http_post', { url, headers, body }). We use it for only the Anthropic API, because the Tauri HTTP plugin still identifies as a browser and Anthropic's CORS policy on this org blocks that.
  2. run() registers four plugins: tauri-plugin-dialog, -http, -sql, -log (debug only) — and the native_http_post handler.
If you add a new Rust command, register its function name in the tauri::generate_handler![...] macro, then call it from TS with invoke().
src-tauri/Cargo.toml
Rust dependencies

Adds: tauri, the four tauri-plugin-* crates, and reqwest for the native HTTP command. The sqlite feature on tauri-plugin-sql is what gives us SQLite (vs MySQL/Postgres alternatives).

src-tauri/tauri.conf.json
App identity, window, build hooks

Highlights:

  • productName: "rl-console", identifier: "com.rocketlane.api-console"
  • frontendDist: "../out" — points to Next.js's static export output
  • devUrl: "http://localhost:3000" + beforeDevCommand: "npm run dev" — Tauri auto-starts Next.js dev
  • Window: 1200×800, resizable, title "RL Console"
  • security.csp: null — CSP disabled. Fine for a local-only app.
src-tauri/capabilities/default.json
Permission allowlist for the Tauri HTTP plugin

Tauri's HTTP plugin will only fetch URLs explicitly allowed here. Currently allowed:

  • https://api.anthropic.com/**
  • https://api.rocketlane.com/**
  • https://*.rocketlane.com/**

SQLite operations load/execute/select/close are also allowed. If you add a new external host, you must add it here or httpFetch() calls will fail silently.

7. Shared types — types/index.ts

Five interfaces that flow through the whole app. Read these once and the rest of the code reads itself.

MappingTemplateOutput of Claude mapping. method, url, headers, body, plus mapping: { PLACEHOLDER → "session_rl_key" | csv_column }.
LogEntryOne log row. status: success | error | skipped | dry_run. Optional statusCode, optional items[] (raw API items from a paginated GET, used for CSV export).
RunSummary{ success, failed, skipped, dryRun } counts.
SavedCurlSQLite row in saved_curls: id, name, curl_command, context, expected_outcome, created_at, last_used_at.
RunRecordSQLite row in runs: same metadata plus mode, totals, dry-run flag.
Pattern: LogEntry.items is only populated for paginated GETs that exceed the in-line EXPAND_LIMIT = 200. The "↓ Items CSV" button in LogPanel appears only when at least one entry has a non-empty items[].

8. lib/ — domain logic

This is the brain of the app. None of these files import React. Each is small and single-purpose.

lib/tauri-fetch.ts
Environment-aware fetch wrapper (10 lines)

Exports httpFetch(url, init). If running inside Tauri (detected via window.__TAURI_INTERNALS__), routes through @tauri-apps/plugin-http — which means the request goes through the Rust HTTP stack and bypasses browser CORS. Outside Tauri (e.g. npm run dev in a regular browser), falls back to window.fetch.

This is what executor.ts uses for Rocketlane API calls.

lib/claude.ts
Curl + CSV → JSON mapping template, via Claude

Exported function: extractMapping(curlCommand, context, expectedOutcome, sampleData, claudeKey). Returns a Zod-validated MappingTemplate.

Posts to https://api.anthropic.com/v1/messages via the Rust native_http_post command. Model is hardcoded: claude-haiku-4-5-20251001.

The system prompt instructs Claude to:

  • Map any auth-looking placeholder to the literal string "session_rl_key"
  • Map all other placeholders to the exact CSV column name
  • Preserve {{PLACEHOLDER}} braces in url/headers/body — don't resolve them

Response handling strips optional ```json fences and validates against MappingSchema (Zod). Any deviation throws.

If you change the system prompt, also re-test the Zod schema — Claude can drop the mapping field if you reword aggressively.
lib/generate-curl.ts
Description → curl command, via Claude

Exported: generateCurl(description, context, claudeKey, csvColumns?, csvSample?, apiDocs?).

Same Anthropic plumbing as claude.ts. The system prompt enforces:

  • Use {{PLACEHOLDER}} syntax
  • Use exact CSV column names if columns are provided
  • Only required params — no optional filters unless asked
  • For GET list endpoints: only pageSize and pageToken

The "only required" rule was added after Claude was returning curls with 50+ optional query params. If you tweak the prompt, re-test against Get all tasks — that endpoint has the longest optional-param list and is the canary.

lib/rl-api-endpoints.ts
Catalogue of Rocketlane endpoints + per-endpoint docs storage

Two responsibilities:

  1. RL_CATEGORIES: hardcoded list of every endpoint the user might want to operate on, grouped by category (Tasks, Projects, Phases, …). Each entry has a key (e.g. tasks.create), a display name, and an HttpMethod. To add a new endpoint: append to the right category — that's it.
  2. loadApiDocs() / saveApiDocs(docs): read/write the user's pasted endpoint docs from localStorage[rl_api_docs] as a { key: text } map. Used by Settings (write) and EndpointPicker / Generate flow (read).
lib/db.ts
SQLite wrapper for saved curls + run history

Lazy-loads @tauri-apps/plugin-sql only inside Tauri (so a regular browser dev session doesn't crash). All exports are no-ops if the DB isn't available.

Schema (created on first initDb()):

saved_curls: id, name UNIQUE, curl_command, context, expected_outcome,
             created_at, last_used_at

runs:        id, curl_name, curl_command, context, expected_outcome,
             mode, total_rows, succeeded, failed, skipped,
             dry_run_count, is_dry_run, created_at

Functions: initDb, getSavedCurls, saveCurl (INSERT OR REPLACE on name), deleteSavedCurl, touchCurl (updates last_used_at), saveRun, deleteRun, getRuns(limit=100).

Where the DB file lives: Tauri stores console.db in the OS app-data dir (on macOS: ~/Library/Application Support/com.rocketlane.api-console/). A .dmg reinstall does not blow it away, but switching between dev (npm run tauri dev) and the bundled .app uses different bundle IDs in some Tauri setups — that's the cause of "my settings disappeared" reports. The Settings export/import JSON is the workaround.
lib/executor.ts
The actual API caller — biggest file in lib/

This is where every real Rocketlane request originates. Read this file once carefully.

Internal helpers

  • fill(value, row, rlKey, mapping) — substitutes {{X}} placeholders in a string using the mapping (session_rl_key → real RL key, otherwise CSV column lookup).
  • fillDeep(val, ...) — same, but recurses into objects/arrays. Used for the body.
  • cleanUrl(url) — for GET, strips query params whose value is empty or still an unresolved {{...}}. Lets you leave optional filters in the curl without sending them.
  • stripEmptyFields(val) — recursively removes empty/unresolved fields from the body. Same idea: optional fields can stay in the curl but won't be sent if blank.
  • summarizeItem(item) / summarizeBody(text) — builds the short "id: 12 · projectName: "Acme"" message shown in the log. INTERESTING_KEYS is the priority list for what to surface.

Public API

  • buildRequest(template, row, rlKey) → { method, url, headers, body }. Used both by executeRow and by MappingPreviewModal to show the resolved request before firing.
  • validateRow(template, row) → string | null. Only fails if a placeholder that appears in the URL path (before ?) maps to an empty CSV column. Body-only and query-only placeholders are not validated here — the API will respond.
  • executeRow(template, row, rlKey, dryRun, rowIndex, onPageFetched?, abortRef?) → Promise<LogEntry[]> — the main act.

Behaviour matrix

ModeWhat happens
Dry runReturns one dry_run entry showing the resolved METHOD URL.
Non-GETValidates → fires once → returns one entry (success/error).
GETAdds pageSize=100 if missing, loops while nextPageToken + hasMore !== false, capped at MAX_PAGES = 200. Fires onPageFetched after every page. Honours abortRef.current.

GET expansion threshold: if allItems.length ≤ EXPAND_LIMIT (200), each item becomes its own LogEntry with row rowIndex + i. Otherwise a single summary entry is returned with the full items[] attached for CSV export.

Two recent bug-fix invariants — don't regress them:
(1) Pagination must check hasMore !== false, not just the presence of nextPageToken — some endpoints return hasMore: false with a stale token.
(2) abortRef must be checked before each page fetch, not after — so a long-running GET stops promptly.
lib/export.ts
Tiny CSV download helper

downloadCSV(filename, data): takes an array of objects, derives columns from the first row, escapes via doubled quotes, and triggers an <a download> click. Used by all three export buttons in LogPanel.

11. app/page.tsx — the orchestrator

~990 lines, but follows a predictable shape. Reading the function names in order is enough to navigate. The file is the only "page" in the App Router (we don't have routing — three views are conditionally rendered inside this single component).

Top-of-file utilities (lines ~20-69)

  • parsePlaceholders(curl) — extracts {{NAME}} tokens from text. Pure.
  • logToRow(entry) — flattens a LogEntry to a CSV-friendly object.
  • curlToName(curl) — auto-derives a short name from a curl, e.g. "DELETE /tasks/{{TaskId}}".
  • parseCurlDirect(curl) — fallback parser for GET runs that don't go through Claude. Handles both -X GET and -G --data-urlencode styles. Used by handleRun() when template === null.

Effects + handlers

  • useEffect on mount — calls initDb(), loads saved curls + runs, reads Claude key from localStorage, loads API docs.
  • useEffect on placeholders — keeps singleValues dict in sync when the curl text changes.
  • handleSaveCurl / handleLoadCurl / handleDeleteLoadedCurl / handleLoadFromHistory — the persistence glue; all delegate to lib/db.ts.
  • handleFileChange — Papa-parses uploaded CSV.
  • handleSaveSettings(claudeKey) — writes to localStorage, updates state.
  • handleGenerateCurl() — calls generateCurl(); passes stored docs only when Context is empty (avoids overwhelming Claude when context is already specific).
  • handlePreviewMapping() — calls extractMapping(), sets template, opens the modal.
  • runRows(rows, tpl?) — the bulk loop. Sets runStartRef.current = Date.now() at the start, then for each row: checks abort, fires executeRow, accumulates summary, recomputes ETA from elapsed / completed × remaining, then sleeps delayMs. On finish, calls saveRun() + clears progress/eta.
  • handleRun() — branches by method: GET → one executeRow with onPageFetched callback; single → one executeRow, save run record; bulk → runRows(csvRows.map(...)).
  • handleRetryFailed() — re-runs only the rows whose last log was error. Reuses the existing template — no Claude call.
  • handleExportErrors / handleExportAll / handleExportItems — three CSV exports. Each calls showToast with a count for confirmation.

Derived flags driving the UI

  • canRun — not running, RL key + curl present, GET runs always (no template needed), non-GET requires template
  • canRetry — bulk mode, has template, summary has at least one failed row
  • hasGetItems — at least one log entry has non-empty items[] (controls "Items CSV" button visibility)

12. Conventions & gotchas

Path aliases

@/lib/foo, @/types, @/app/components/X — all resolve from project root. Use them; relative ../../ imports get ugly fast.

"use client" everywhere

Every component file starts with 'use client'. There is no server component in this app — static export wouldn't ship them anyway.

Two HTTP code paths — choose correctly

For…Use…Why
Anthropic / Claude callsinvoke('native_http_post', ...) from @tauri-apps/api/coreBrowser CORS blocks Anthropic on this org. Pure Rust reqwest sidesteps it.
Rocketlane API callshttpFetch() from lib/tauri-fetch.tsTauri HTTP plugin works fine here, and gracefully falls back to fetch when running outside Tauri.

Where settings actually live (and why they "evaporate")

  • Claude key + per-endpoint docs → localStorage.
  • Saved curls + run history → SQLite at ~/Library/Application Support/com.rocketlane.api-console/console.db.
  • If the bundle identifier in tauri.conf.json changes, or if a switch between npm run tauri dev and a built .app uses different effective storage, the user sees "blank slate" on launch. The Settings → Export/Import JSON is the safety net.

Method detection

Two sources of method:

  1. detectedMethod — derived from the curl text via regex.
  2. pickedMethod — set when the user picks an endpoint in EndpointPicker.

effectiveMethod = pickedMethod ?? detectedMethod. Editing the curl manually clears pickedMethod (see the onChange on the textarea: setPickedMethod(null)). This is intentional — manual edits should win.

Placeholder validation

Only URL-path placeholders are required. Body and query placeholders are optional — stripEmptyFields + cleanUrl in the executor remove them before sending. This is what lets users keep "kitchen-sink" curls and pass partial CSVs.

The RL_API_KEY placeholder is special

Wherever the curl uses {{RL_API_KEY}}, the mapping always points to session_rl_key, and fill() swaps in the in-memory rlKey at request time. Never show this in CSV column dropdowns or the single-value form — it's filtered out everywhere via p !== 'RL_API_KEY'.

Aborting

abortRef is a plain useRef(false). The Abort button flips it to true. Both runRows (between rows) and executeRow's GET loop (between pages) check it. Don't replace it with useState — the loop won't see updates because of closure capture.

ETA computation

In runRows, after each row: avgMs = elapsed / completed, remainingMs = remaining × avgMs. First-row estimate is unavoidably rough but converges fast. ETA is only shown for bulk runs (not GET fetches, not single runs).

Dead code to be aware of

  • app/components/SettingsModal.tsx — Gemini-era leftover.
  • @google/genai in package.json — unused.
  • @anthropic-ai/sdk — installed but bypassed in favour of the Rust command.
  • public/rl.svg — corrupt (binary in an SVG file). Use rli.svg.
  • README.md — stock create-next-app readme.

13. Common dev tasks

Add a new Rocketlane endpoint to the picker

  1. Open lib/rl-api-endpoints.ts.
  2. Add a { key, name, method } entry under the right category in RL_CATEGORIES, or add a whole new category.
  3. Done — the picker, settings page, and badges pick it up automatically.

Allow a new external HTTP host

  1. Open src-tauri/capabilities/default.json.
  2. Add the URL pattern under the "http:allow-fetch" permission's allow array.
  3. Rebuild — capabilities are baked at build time.

Tweak how Claude generates curls

Edit the SYSTEM string in lib/generate-curl.ts. After changes, smoke-test against Get all tasks (most over-eager endpoint) and a typical POST like Create a task.

Tweak how Claude maps placeholders

Edit the SYSTEM in lib/claude.ts — but make sure the JSON it returns still matches MappingSchema. The Zod parse will throw with a useful error if not.

Add a new column to run history

  1. Add the field to RunRecord in types/index.ts.
  2. Update the CREATE TABLE in lib/db.ts → initDb() (and write a migration if the DB is already in production).
  3. Update saveRun() to include the field.
  4. Add a column in HistoryView.tsx's table.

Add a new top-level view (e.g., "Stats")

  1. Create app/components/StatsView.tsx.
  2. Add 'stats' to the activeView union in page.tsx.
  3. Add a button in the header nav array (['operation', 'history', 'settings'] as const).
  4. Add a render branch in the main flex container.

Change the splash duration / animation

app/components/SplashScreen.tsx — adjust the two setTimeouts. Animation keyframes live in app/globals.css.

Change the model

lib/claude.ts and lib/generate-curl.ts both have a const MODEL = ... at the top. Update both. (Or refactor into a shared constant — currently duplicated.)

npm run lint

Smoke test after any change

  1. Open the app, dismiss splash.
  2. Settings → paste Claude key, paste docs for at least one endpoint.
  3. Operation → paste RL key in session, type a description, click Generate.
  4. Click Run with Dry Run on — confirm preview looks right.
  5. For a GET: turn off Dry Run, run, confirm pagination + ETA + abort all behave.
  6. For a POST/PUT/DELETE: upload a 3-row CSV, Preview Mapping, confirm.
  7. History tab → run shows up. Retry-failed if anything errored.
